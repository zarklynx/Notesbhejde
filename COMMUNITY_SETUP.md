# Community features

Firebase Authentication and the existing Firestore notes/file backend remain unchanged. Saved folders, favourites, recent notes, comments, public rooms, public profiles, notifications, and engagement statistics now use the authenticated `/api/community` endpoint on the existing Masterji Worker.

The hosted endpoint is already the frontend default. Teammates need the existing Firebase client configuration and `npm install`, then `npm run dev`; no Runware key is required in the browser. AI secrets remain on Cloudflare.

## Storage and deployment

Community tables currently share the existing D1 database via the `VOICE_USAGE` binding; table names do not overlap voice usage. Apply the additive schema before deploying on another account:

```sh
npx wrangler d1 execute masterji-voice-usage --config masterji-worker/wrangler.jsonc --remote --file masterji-worker/community.sql
npx wrangler deploy --config masterji-worker/wrangler.jsonc
```

Add the deployed frontend origin to `ALLOWED_ORIGINS` before using a different website domain. Keep Firebase project ID aligned with the frontend. Never commit secrets or service-account JSON.

## Behaviour

1. Saved is a separate library with folders, not an academic category. Deleting a folder moves its saved notes to General; it never deletes the original note.
2. Public chat starts in Default; Create room is inside the room selector. Updates poll every 15 seconds while visible and refresh immediately after your own changes.
3. Favourites are unique per user/note. Views count once per signed-in non-owner reader per note per UTC day. Profiles show separate competition ranks for views and favourites; zero activity is unranked. These are activity ranks, not academic marks.
4. Notifications are generated by the server for favourites and comments on your notes, not arbitrary client writes. Read state is remembered on this browser.
5. Note ownership and public visibility are verified against the existing Firestore notes API. Clients cannot assign another owner to inflate rankings.
6. Existing Firestore community data is not deleted or automatically transferred. Counts begin with recorded Cloudflare activity. Message windows show the latest 100 messages.

## Verification

```sh
node --test server/*.test.js masterji-worker/community.test.js
npm run build
npm run lint
```

`scripts/community-live-test.mjs` and `scripts/masterji-live-test.mjs` use temporary Firebase test accounts and the actual deployed APIs; they are optional, not part of startup. The community test prints fixture user IDs for administrator cleanup of its temporary room/profile/views/notifications in D1. Auth accounts, messages, saved entries and favourites are cleaned up by the script. Do not run these against a production audience without intending to create temporary test activity.
